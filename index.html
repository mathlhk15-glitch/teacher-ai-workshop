0. 오늘 무엇을 했나?

AI에게 질문만 해본 것이 아니라, 반복 업무용 Gem을 하나 만들고, 내가 원하는 웹페이지를 만든 뒤, GitHub Pages로 실제 웹주소까지 연결하는 전체 흐름을 체험했습니다.

STEP 1Google/GitHub 준비
STEP 2Gem 1개 만들기
STEP 3나만의 웹 만들기
STEP 4GitHub Pages 공개
핵심: 코드를 외우는 연수가 아니었습니다. 원하는 내용을 말로 적고 → AI에게 만들게 하고 → 결과를 웹주소로 연결하는 방법을 익힌 것입니다.
  • Gem이 ‘긴 지시문을 저장해 반복해서 쓰는 도구’라는 점을 이해했다.
  • 웹페이지 재료 6줄을 만들고 Gemini에 전체 프롬프트를 넣어 보았다.
  • index.html 파일 또는 전체 HTML 코드를 확보했다.
  • GitHub 저장소에 index.html을 넣고 Pages 공개 과정을 해 보았다.

2. Gem 실습 1회

연수에서는 여러 Gem을 만들지 않고 하나만 체험했습니다. 목적은 Gem 메뉴를 외우는 것이 아니라, 좋은 지시문을 한 번 저장해 두고 짧은 요청만 반복해서 사용하는 원리를 경험하는 것입니다.

실습 사이트 열기 ↗

다시 따라하기

  1. 위 Gem 실습 사이트를 엽니다.
  2. Gemini에 로그인합니다.
  3. 실습 사이트에서 지정된 Gem 항목으로 이동합니다. 연수에서는 PROMPT 10 · 교사 프롬프트 개선 Gem을 사용했습니다.
  4. ① Gem 지침 복사를 누릅니다.
  5. Gemini에서 Gems 탐색하기 → 새 Gem으로 들어갑니다.
  6. 이름을 정하고, 요청 사항(지침)에 복사한 내용을 붙여넣은 뒤 저장합니다.
  7. 실습 사이트로 돌아와 ② 채팅 명령어 복사를 누릅니다.
  8. 방금 만든 Gem의 채팅창에 붙여넣고 실행합니다.
  9. 결과가 나오면 짧은 후속 요청을 한 번 해봅니다.
표 형태로 다시 정리해줘.
Gem 메뉴가 보이지 않는 경우: 메뉴를 찾느라 시간을 쓰지 않습니다. 실습 사이트의 Gem 지침을 일반 Gemini 새 채팅에 먼저 붙여넣고, 이어서 채팅 명령어를 붙여넣으면 같은 원리를 체험할 수 있습니다.

우리가 확인한 Gem의 핵심

긴 지시문역할·대상·작업·출력 형식·주의사항을 한 번 저장
짧은 요청실제 업무 때는 필요한 자료와 요청만 입력
반복 활용비슷한 업무를 매번 처음부터 설명하지 않아도 됨

3. 나만의 웹 만들기

연수 당시 Padlet에서는 1. 빈 칸 채우기 → 2. 빈 칸 채우기 예시 → 3. 프롬프트 순서로 진행했습니다. Padlet이 없어도 아래 내용을 그대로 사용하면 됩니다.

나는 코딩을 잘 모른다. 아래 [내 재료]를 이용해 나만의 웹페이지를 완성해줘.

조건:
- 하나의 index.html로 완성
- HTML, CSS, JavaScript를 모두 한 파일 안에 포함
- 별도 설치 없이 Chrome 또는 Edge에서 바로 작동
- 외부 이미지, 외부 폰트, 외부 라이브러리, API는 사용하지 않기

- 웹페이지 문구는 쉽고 짧게 작성
- 글자는 충분히 크게, 카드 형태로 깔끔하게 구성
- 내가 선택한 기능이 실제로 작동하게 만들기
- 개인정보 입력칸, 로그인, 회원가입 기능은 만들지 않기
- 내가 제공하지 않은 사실은 임의로 만들어 넣지 않기
- 오류가 없는지 확인하기
- 파일 생성이 지원되지 않는 환경이라면 처음부터 끝까지 생략 없는 전체 HTML 코드를 하나의 코드블록으로 함께 제공하기
- 코드 일부만 보여주거나 중간을 생략하지 않기

4. HTML 결과 확인·수정

Gemini 결과무엇을 하나완료 기준
A. index.html 파일이 나옴다운로드 → 파일명이 정확히 index.html인지 확인 → 더블클릭Chrome/Edge에서 내 웹이 열림
B. 파일 없이 코드만 나옴코드 전체를 복사해 둠. 메모장에 저장하지 않음생략 없는 전체 코드 확보
C. 코드가 중간에 생략됨아래 재요청 문장을 그대로 붙여넣음전체 코드 확보
 
처음부터 끝까지 생략 없는 전체 HTML 코드를 하나의 코드블록으로 다시 제공해줘.
파일명이 정확히 index.html이 아닐 때: Windows에서 확장자를 억지로 바꾸지 않습니다. 뒤의 GitHub Create new file 방식으로 전체 코드를 붙여넣습니다.

코드만 나왔을 때 · index.html 파일 만들기

Gemini가 파일 대신 코드를 보여줘도 메모장을 사용할 필요가 없습니다. 아래 칸에 전체 HTML 코드를 붙여넣고 다운로드하세요. 입력한 코드는 이 브라우저 안에서만 처리됩니다.

※ 코드가 일부 생략되었다면 먼저 Gemini에 “처음부터 끝까지 생략 없는 전체 HTML 코드”를 다시 요청하세요.

수정은 GitHub에 올리기 전에 1회

초보자에게 가장 단순한 순서는 생성 → 확인 → 수정 → 최종본 업로드입니다.

방금 만든 웹페이지에서 글자 크기와 버튼을 조금 더 크게 해줘.
내용과 기능은 그대로 유지해줘.
수정 결과도 다운로드해서 바로 사용할 수 있는 index.html 파일로 생성해줘.
파일을 직접 생성할 수 없다면 수정된 전체 HTML 코드를 처음부터 끝까지 생략 없이 하나의 코드블록으로 제공해줘.

원하는 경우 위 첫 문장을 “색상을 더 차분하게”, “모바일에서 더 보기 좋게”, “검색 기능을 추가해줘” 등으로 바꿔 사용할 수 있습니다.

5. 최종 결과를 GitHub에 저장

GitHub는 웹페이지 파일을 보관하고, 다음 단계에서 GitHub Pages로 웹주소를 만드는 데 사용했습니다.

5-1. 저장소 만들기

  1. GitHub 오른쪽 위 + 클릭
  2. New repository 클릭
  3. Repository name에 my-web 입력
  4. Public 선택
  5. Create repository 클릭
Public 저장소 주의: 학생 실명·사진·성적·상담·연락처·학교 내부 민감자료는 올리지 않습니다.

5-2A. index.html 파일이 있는 사람

  1. Add file → Upload files
  2. 다운로드 폴더에서 index.html 선택
  3. Commit changes

5-2B. 코드만 있는 사람

  1. Add file → Create new file
  2. 파일 이름 칸에 정확히 index.html 입력
  3. Gemini에서 복사한 전체 HTML 코드를 큰 입력창에 붙여넣기
  4. Commit changes
다음 단계로 넘어가는 기준: 저장소 첫 화면에 파란 링크로 index.html이 보이면 성공입니다.

6. GitHub Pages로 웹주소 만들기

  1. 저장소 상단 Settings 클릭
  2. 왼쪽 메뉴 Pages 클릭
  3. Build and deployment의 Source에서 Deploy from a branch 선택
  4. Branch: main
  5. Folder: /(root)
  6. Save 클릭
  7. 잠시 기다린 뒤 새로고침
  8. Visit site 또는 표시된 주소 클릭
배포에는 시간이 걸릴 수 있습니다. 주소가 바로 안 열려도 main / root 설정을 완료하고 배포가 시작된 상태면 정상입니다.

내 GitHub Pages 주소 미리 계산하기

사용자명과 저장소 이름을 입력하면 일반적인 GitHub Pages 주소 형태를 보여줍니다.

https://사용자명.github.io/저장소이름/

※ 실제 공개 주소는 GitHub의 Settings → Pages 화면에 표시되는 주소를 최종 기준으로 확인하세요.

마지막 확인

  • PC에서 내 공개 웹주소를 열어보았다.
  • 휴대전화에서도 같은 주소를 열어보았다.
  • 내 웹주소를 따로 저장해 두었다.
